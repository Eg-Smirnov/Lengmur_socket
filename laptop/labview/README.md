# Работа с LabVIEW

## Среда разработки

- Целевая среда — **LabVIEW 2019, 64-bit**. Проект переводится с LabVIEW 2015,
  чтобы использовать Python Node для разбора JSON и прикладной логики.
- Python Node появился в LabVIEW 2018, поэтому клиент с Python Node несовместим с
  LabVIEW 2015. Для разработки и запуска потребуются LabVIEW 2019 или подходящая
  среда выполнения и установленный 64-битный Python версии, поддерживаемой
  LabVIEW 2019. Точные зависимости следует проверить перед установкой на
  лабораторные компьютеры.
- Python-функции вызываются из блок-диаграмм. Пользовательский интерфейс,
  очереди, жизненный цикл транспорта и VISA остаются в LabVIEW. Пользователь
  вносит изменения в LabVIEW, а агент помогает с интерфейсом, настройками,
  блок-диаграммами, Python Node и ошибками.

## Формат работы с агентом

Пользователь прикладывает скриншоты текущего состояния LabVIEW в папку
[`screenshots/`](screenshots/) и задаёт вопрос. Изображения в этой папке
игнорируются Git и не попадут в коммиты.

Перед ответом агент должен изучить относящиеся к вопросу файлы проекта и
скриншоты, а затем найти недостающую информацию в документации NI или других
надёжных источниках. Нужно предлагать конкретные действия и объяснять, где их
выполнить в LabVIEW 2019. Если подход зависит от версии или скриншота недостаточно,
следует явно обозначить это и уточнить недостающие детали. Не предполагайте, что
пользователь может автоматически сгенерировать или применить изменения к VI.

### Просмотр скриншотов и точка продолжения

- Перед ответом получайте полный список файлов в `screenshots/`, упорядоченный по
  времени, и просматривайте **все** скриншоты, добавленные после последнего
  просмотренного. Нельзя считать просмотром только открытие самого нового файла.
- После разбора скриншотов указывайте в ответе имя последнего просмотренного файла
  (`Точка просмотра скриншотов: <имя файла>`). В следующем ходе используйте его как
  контрольную точку и просмотрите все более новые файлы по порядку.
- Если контрольной точки нет в контексте, восстановите её по предыдущим ответам;
  если восстановить нельзя — просмотрите все доступные скриншоты, относящиеся к
  текущей задаче, в хронологическом порядке.
- Для сравнения изменений при необходимости повторно открывайте предыдущий
  контрольный скриншот вместе со всеми новыми. Если новых скриншотов нет, сообщите
  об этом и не представляйте старый скриншот как новое состояние.

При обсуждении совместимости указывайте, что Python Node требует LabVIEW 2018
или новее, а этот проект нацелен на LabVIEW 2019. Компьютеры с LabVIEW 2015 без
подходящей среды выполнения не смогут запускать новую версию клиента.
