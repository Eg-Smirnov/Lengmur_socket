# Lengmur Socket

ESP32-WROOM-32 обменивается с компьютерным приложением через USB Serial со
скоростью 115200 бод. Код транспорта находится в
`esp/src/drivers/serial_protocol/`, а общая схема настроек — в `config.json`.

## Кадр протокола

Serial рассматривается как поток байтов. Каждый пакет передаётся в кадре:

| Смещение | Размер | Поле |
| ---: | ---: | --- |
| 0 | 2 | сигнатура `4C 53` (`LS`) |
| 2 | 1 | тип в битах 7…5, версия в битах 4…0 |
| 3 | 2 | размер payload в **байтах**, `uint16`, little endian |
| 5 | N | payload |
| 5 + N | 4 | CRC32 заголовка и payload, little endian |

Размер указан в байтах, поскольку payload бывает как JSON, так и двоичным.
Ограничение `uint16` позволяет дробить большие данные на пакеты и не требует
неограниченного буфера. Текущая реализация принимает payload до 2048 байт.
CRC32 используется во всех типах кадров: отражённый полином `0xEDB88320`,
начальное значение `0xFFFFFFFF`, финальный XOR `0xFFFFFFFF` (тот же вариант,
что `zlib.crc32`). Версия протокола — 1.

Реализованные типы пакетов:

| Тип | Направление | Payload |
| ---: | --- | --- |
| 0 | компьютер → ESP32 | команда JSON в UTF-8 |
| 1 | ESP32 → компьютер | ответ JSON в UTF-8 |

Типы 2…7 зарезервированы для будущего расширения протокола. Формат измерений в
этом документе пока не определяется. Получатель ищет сигнатуру и после повреждённого
кадра продолжает поиск следующей сигнатуры.

## Команды и настройки

Чтение и запись настроек остаются JSON-командами, но JSON теперь находится
внутри кадра типа 0 и не завершается переводом строки.

```json
{"op":"get"}
{"op":"get","field":"sample_rate"}
{"op":"set","field":"sample_rate","value":1000}
{"op":"set","config":{"sample_rate":1000,"min_voltage":-10,"max_voltage":10,"shunt_res":"auto"}}
{"op":"measure_once"}
```

Успешный ответ имеет поле `"ok":true`. Ошибка имеет вид
`{"ok":false,"error":"код"}`. Список полей, типы и значения по умолчанию задаются в `config.json`. После его
изменения выполните `python tools/generate_config.py` и сохраните созданный
`esp/src/drivers/serial_protocol/config_generated.h`.

Команда `measure_once` выполняет одно диагностическое чтение пары АЦП и
возвращает сырые знаковые коды вместе с фактически выбранным шунтом:

```json
{"ok":true,"sample":{"voltage_raw":123,"current_raw":-45,"shunt_res":10000000}}
```

При настройке `shunt_res: "auto"` диагностический режим временно использует
шунт по умолчанию 10 МОм. Пересчёт сырых кодов в физические величины пока не
выполняется.

## Сборка

```powershell
arduino-cli compile --profile esp32_wroom_32 esp
```

Команда только компилирует прошивку и не загружает её на плату.
