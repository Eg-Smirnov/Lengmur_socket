# Обработка ошибок

Клиентская библиотека передаёт ошибки через стандартный LabVIEW error cluster:

- `status` — `TRUE`, если операция завершилась ошибкой.
- `code` — числовой код ошибки.
- `source` — источник или описание ошибки.

## Правила распространения

- Соединяйте `error out` одного VI с `error in` следующего. Не разрывайте цепочку
  между кодированием, транспортом и обработкой ответа.
- Проверки в `Encode Frame.vi` идут последовательно: сначала тип пакета, затем
  длина payload. Узел `Error Cluster From Error Code` сохраняет уже полученную
  ошибку. Поэтому при нескольких проблемах возвращается первая: существующая
  входная ошибка имеет приоритет над новой; ошибка типа — над ошибкой длины.
- При `error out.status = TRUE` выходные данные VI не являются результатом,
  который можно отправлять или обрабатывать. В частности, вызывающий код не
  должен передавать `frame bytes` в транспорт при ошибке. Сам `Encode Frame.vi`
  не обязан заменять выходную строку пустой.
- Библиотека возвращает error cluster и не должна сама показывать диалоговое
  окно. Решение показать ошибку пользователю или записать её в журнал принимает
  верхний уровень приложения.
- Ошибка транспортного или кодирующего VI в error wire отличается от ошибки
  команды прошивки: ответ прошивки `{"ok":false,"error":"..."}` — это JSON
  payload. Его формат описан в [спецификации команд](../../protocols/commands.md).

## Ошибки, назначенные библиотеке

### 5001 — TCP-транспорт не реализован

- Возникает в `Open Transport.vi`, `Read Transport.vi` и `Write Transport.vi`.
- Условие: выбран Ethernet TCP.
- Сообщение: `TCP transport not implemented yet`.

### 5002 — недопустимый тип пакета

- Возникает в `Encode Frame.vi`, если `packet_type > 7`.
- Сообщение: `packet type too high`.

### 5003 — payload превышает предел кадра

- Возникает в `Encode Frame.vi`, если размер payload больше 2048 байт.
- Сообщение: `payload too long`.

Коды 5001–5003 принадлежат клиентской библиотеке и не являются кодами ошибок
прошивки. Для новых ошибок выделяйте отдельный код и обновляйте этот список.
NI резервирует диапазон 5000–9999 для пользовательских кодов; см.
[правила NI по пользовательским кодам ошибок](https://www.ni.com/docs/gd-GB/bundle/labview/page/defining-custom-error-codes-using-the-general-error-handler-vi.html).

Ошибки VISA, например отсутствие COM-порта или ошибка записи, остаются исходными
ошибками NI-VISA и должны проходить по той же error wire. Не заменяйте их кодами
5001–5003.

## Проверочные сценарии

Ожидаемый контракт для ручной проверки в LabVIEW:

- Тип 0, payload до 2048 байт, `error in` без ошибки: `status = FALSE`, `code = 0`.
- Тип 8 с payload допустимого размера: `status = TRUE`, код `5002`.
- Тип 0 и payload размером 2049 байт: `status = TRUE`, код `5003`.
- Тип 8 и payload 2049 байт одновременно: возвращается код `5002`, так как
  проверка типа выполняется первой.
- Если входной error cluster уже содержит ошибку, его `status`, `code` и `source`
  должны пройти дальше без замены.

При любом `status = TRUE` значение `frame bytes` не использовать. Успешные
контрольные кадры `Encode Frame.vi` приведены в
[документе кодирования](frame-encoding.md).
