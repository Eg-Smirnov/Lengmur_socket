# Кодирование Serial-кадра

Документ описывает текущий контракт внутреннего
[`Encode Frame.vi`](../../../laptop/labview/Internal/Protocol/Encode%20Frame.vi).
Полный формат кадра и CRC определены в общей
[спецификации Serial](../../protocols/serial.md).

## Входы и выходы

- `packet_type` — числовой тип кадра. VI принимает значения 0–7. Типы 3–7
  зарезервированы протоколом и не должны использоваться приложением до их
  определения.
- `payload` — строка LabVIEW с байтами payload. VI не сериализует JSON и не
  преобразует кодировку.
- `error in` — ошибка, поступившая от предыдущего VI.
- `frame bytes` — бинарная строка LabVIEW с целым кадром.
- `error out` — ошибка входных данных или унаследованная ошибка.

Если payload содержит JSON, вызывающий код должен заранее получить его UTF-8
байты и передать их в `payload`. Строка `frame bytes` — бинарные данные, а не
текст для отображения или перекодирования.

## Формат и вычисление

Кадр собирается в следующем порядке:

1. Сигнатура `4C 53` (`LS`).
2. Байт типа и версии: `packet_type * 32 + 1` (версия протокола 1).
3. Длина payload как U16 little-endian: младший байт, затем старший.
4. Байты payload без изменений.
5. CRC-32 по заголовку и payload, в little-endian порядке.

Используются отражённый полином `0xEDB88320`, начальное значение
`0xFFFFFFFF` и финальный XOR `0xFFFFFFFF`. Общие ограничения кадра и JSON
описаны в [спецификации Serial](../../protocols/serial.md): общий payload кадра —
до 2048 байт, JSON-команды и ответы прошивки — до 256 байт. Текущий
`Encode Frame.vi` проверяет общий предел 2048 байт; ограничение JSON относится к
вызывающему коду, формирующему команду.

## Контрольные примеры

Эти примеры проверены запуском VI в LabVIEW с отображением `frame bytes` в
шестнадцатеричном виде:

- **Тип 0, пустой payload:** `4C 53 01 00 00 2E 88 5B 83`.
- **Тип 0, ASCII payload `123456789`:**
  `4C 53 01 09 00 31 32 33 34 35 36 37 38 39 C6 1B A2 C3`.

Проверки некорректного типа и слишком длинного payload описаны в
[документе об ошибках](error-handling.md).
