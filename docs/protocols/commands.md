# Команды и ответы

JSON-команды передаются в UTF-8 внутри Serial-кадра типа 0 и не завершаются
переводом строки. Ответ ESP32 передаётся кадром типа 1.

Размер сериализованной JSON-команды или JSON-ответа ограничен 256 байтами, хотя
двоичный формат кадра допускает payload до 2048 байт. Клиент проверяет размер
UTF-8-представления команды до отправки. На корректный кадр с JSON-командой
размером больше 256 байт прошивка отвечает:

```json
{"ok":false,"error":"request_too_large"}
```

## Последовательность обмена

Прикладной протокол пока не содержит идентификатора запроса. Клиент должен
отправлять следующий запрос только после получения ответа на предыдущий либо
после истечения его тайм-аута. Одновременное ожидание нескольких ответов не
поддерживается.

Это ограничение не требует от прошивки немедленно сформировать ответ в той же
итерации `ControlTask`: запрос и соответствующий ответ могут последовательно
обрабатываться через локальную очередь и межъядерную транзакцию. Для нескольких
одновременных запросов в будущем потребуется расширить прикладной протокол
идентификатором.

## Настройки

Поддерживаются чтение всей конфигурации или отдельного поля и запись отдельного
поля или полного объекта:

```json
{"op":"get"}
{"op":"get","field":"sample_rate"}
{"op":"set","field":"sample_rate","value":1000}
{"op":"set","config":{"sample_rate":1000,"min_voltage":-10,"max_voltage":10,"shunt_res":"auto"}}
```

При `set` прошивка передаёт настройки задаче измерительного тракта, применяет их
на Core 0, сохраняет в NVS и только после межъядерного commit возвращает
успешный ответ. В текущем состоянии `Idle` это происходит сразу; после появления
sweep-сбора изменение будет ожидать границы sweep. Значению `"auto"` временно
соответствует шунт 10 МОм.

Состав и типы полей определены в [`config.json`](../../config.json) и описаны в
[разделе конфигурации](../firmware/configuration.md).

## Результат выполнения

Успешный ответ содержит поле `"ok":true`. Ошибка имеет вид:

```json
{"ok":false,"error":"код"}
```

Ошибки кадра и очереди возвращаются тем же форматом:

| Код | Причина |
| --- | --- |
| `invalid_crc` | CRC32 принятого кадра не совпадает с вычисленной |
| `unsupported_version` | кадр использует неподдерживаемую версию |
| `unexpected_packet_type` | входящий кадр имеет тип, отличный от команды |
| `request_too_large` | JSON-payload корректного кадра превышает 256 байт |
| `queue_full` | готовое событие или межъядерная команда не поместились в свою очередь |

Формат внешнего кадра описан в [документе Serial-транспорта](serial.md).

Команды прежних диагностических прототипов `measure_once`, `get_out_state` и
`toggle_out` текущей прошивкой не поддерживаются.
