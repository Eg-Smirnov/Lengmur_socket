# Команды и ответы

JSON-команды передаются в UTF-8 внутри Serial-кадра типа 0 и не завершаются
переводом строки. Ответ ESP32 передаётся кадром типа 1.

После запланированной реорганизации размер сериализованной JSON-команды или
JSON-ответа будет ограничен 256 байтами, хотя бинарный формат кадра допускает
payload до 2048 байт. Клиент должен будет проверять размер UTF-8-представления
команды до отправки. На корректный кадр с JSON-командой размером больше 256 байт
прошивка будет отвечать:

```json
{"ok":false,"error":"request_too_large"}
```

Текущая реализация ещё использует общий предел кадра 2048 байт и не возвращает
эту ошибку.

## Последовательность обмена

Прикладной протокол пока не содержит идентификатора запроса. Клиент должен
отправлять следующий запрос только после получения ответа на предыдущий либо
после истечения его тайм-аута. Одновременное ожидание нескольких ответов не
поддерживается.

Это ограничение не требует от прошивки немедленно сформировать ответ в том же
проходе главного цикла: запрос и соответствующий ответ могут последовательно
обрабатываться через общую очередь приложения. Для нескольких одновременных
запросов в будущем потребуется расширить прикладной протокол идентификатором.

## Настройки

Поддерживаются чтение всей конфигурации или отдельного поля и запись отдельного
поля или полного объекта:

```json
{"op":"get"}
{"op":"get","field":"sample_rate"}
{"op":"set","field":"sample_rate","value":1000}
{"op":"set","config":{"sample_rate":1000,"min_voltage":-10,"max_voltage":10,"shunt_res":"auto"}}
```

После успешной записи `shunt_res` прошивка сразу устанавливает соответствующий
адрес ADG5408. Запускать `measure_once` для применения нового сопротивления не
требуется. Значению `"auto"` временно соответствует шунт 10 МОм.

Состав и типы полей определены в [`config.json`](../../config.json) и описаны в
[разделе конфигурации](../firmware/configuration.md).

## Однократное измерение

Команда `measure_once` выполняет одно диагностическое чтение пары АЦП:

```json
{"op":"measure_once"}
```

Ответ содержит сырые знаковые коды напряжения и тока и фактически выбранный
шунт:

```json
{"ok":true,"sample":{"voltage_raw":123,"current_raw":-45,"shunt_res":10000000}}
```

При настройке `shunt_res: "auto"` диагностический режим временно использует
шунт 10 МОм. Пересчёт сырых кодов в физические величины пока не выполняется.

## Управление силовым выходом

При запуске ESP32 вывод `OUT_EN` (GPIO17) настраивается как выход и получает
безопасный уровень LOW. Текущее состояние можно прочитать командой:

```json
{"op":"get_out_state"}
```

Команда `toggle_out` изменяет уровень на противоположный. Обе команды возвращают
фактическое состояние выхода:

```json
{"ok":true,"out_enabled":true}
```

## Результат выполнения

Успешный ответ содержит поле `"ok":true`. Ошибка имеет вид:

```json
{"ok":false,"error":"код"}
```

Формат внешнего кадра описан в [документе Serial-транспорта](serial.md).
